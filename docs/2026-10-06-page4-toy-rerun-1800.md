## The short version

- **The reproduction check passed exactly.** Run so that they fit on 420
  episodes, the new scripts reproduce the committed records value for value:
  29,154 values across the twelve toy models' rows and read files, and 11,712
  across the competing solver's files, with **none different**. So the
  scripts change nothing except the fitting count and the pool the reads are
  fitted on (method, section 4).
- **The 1,800 run has not been made.** The method's time limit fired. The
  reproduction pass took **4 hours 8 minutes** (19:04 to 23:12). The method
  says to stop if the job would run past about two hours, so the 1,800 pass
  was stopped about one minute after it started. Its first three processes
  (arm T, seeds 0 to 2) had written only their read files and no row. Those
  files were deleted unread. **No 1,800 figure exists and none was seen.**
- **Why it was slow: other jobs, not this one** (MEASURED). While it ran,
  other sessions' jobs were running on the same laptop: among them, another
  worktree's measurement of a 30-million-parameter check model. The 15-minute
  load average stood at **160** when the pass ended. The ten-core laptop is
  fully busy at a load of about 10. Arm T's three models, which ran first and
  mostly before that load built up, took 422 to 429 seconds each, two at a
  time slower than the committed single runs (about 200 seconds). Later
  models took 1,076 to 6,055 seconds.

## What it would take to finish

**Estimate (ARGUED from the committed timings).** On an otherwise idle laptop,
the 1,800 pass is the same work as the committed fresh-fit run (66 minutes
for the twelve models, one at a time) plus the solver (14 minutes): **about
80 minutes**. Two things back this up. A timing of the straight-line fit on
random data showed the same time per fit at 1,800 rows as at 420 (about
0.009 seconds). And nearly all of the run is the transplant passes, which
the ruling leaves on 600 pairs. Under today's load it would be about four
hours again. The reproduction pass does not need to be repeated; its outputs
are committed here.

To finish, on a quiet laptop, from `experiments/rehearsal-successor-measure/src/`:

    PY=~/Code/minimum-viable-mind/.venv/bin/python
    OUT=../out-page4-rerun-1800
    for s in 0 1 2; do $PY page4_models_1800.py --pool 1980 --out $OUT/models-1800 --arm T --seed $s; done
    for a in C M F; do for s in 0 1 2; do
      $PY page4_models_1800.py --pool 1980 --out $OUT/models-1800 --arm $a --seed $s; done; done
    $PY page4_models_1800.py --summarise $OUT/models-1800
    $PY page4_solver_1800.py --pool 1980 --out $OUT/solver-1800
    $PY page4_compare.py

(This is the second half of `page4_run_all.sh`, one model at a time. Arm T's
seeds must come first: every other arm reads arm T's site set for the
rider.) Whoever runs it should first check that nothing else heavy is
running (`uptime`; a load average well under 10).

## The reproduction check, and how to recompute it

**Command** (from `experiments/rehearsal-successor-measure/src/`):

    sh page4_run_all.sh 4      # the first half: the two runs at 420, then the check

or by hand:

    PY=~/Code/minimum-viable-mind/.venv/bin/python
    OUT=../out-page4-rerun-1800
    for s in 0 1 2; do $PY page4_models_1800.py --pool 600 --out $OUT/models-420 --arm T --seed $s; done
    for a in C M F; do for s in 0 1 2; do
      $PY page4_models_1800.py --pool 600 --out $OUT/models-420 --arm $a --seed $s; done; done
    $PY page4_models_1800.py --summarise $OUT/models-420
    $PY page4_solver_1800.py --pool 600 --out $OUT/solver-420
