# Ruling 2026-10-04: Minimum Viable Mind work is no longer scheduled on future dates

*Recorded 2026-10-04 (Pacific) by the Claude Code session that ran the first
half of the registration review on proposal version 4, at John's instruction
("file the timing ruling"). **Authorship: john.** He gave the ruling in a
planning session on 2026-10-04. This session did not see that planning session.
It has the ruling from John's own message opening this session, which states it
as follows, and that wording is what is recorded here. No compute was launched
and no money was spent.*

*Written under the workspace plain-language rule.*

## The ruling

As John's message put it: "John ruled 2026-10-04: stop scheduling Minimum
Viable Mind work on future dates. Steps run as soon as their prerequisites are
met. docs/weekend-roadmap-2026-09-24.md no longer sets timing; kill dates
2026-10-18 and 2026-11-01 remain outer limits only."

In the same planning session he also said: "The goal is to run everything as
soon as possible based on what pre-requisites need to be finished first". The
same message reports that he said "everything is approved", about the
registered training.

## What it means in practice

- **No step waits for a date or a weekend.** Each step runs as soon as what it
  waits on is done. The order of work is set by what each step waits on, as in
  the TimeAssembler roadmap for the project and in version 4's section 11
  ("Order of work, and where it stops").
- **The weekend roadmap no longer sets timing.**
  `docs/weekend-roadmap-2026-09-24.md` and its structured copy,
  `data/roadmap.toml`, stay on the record as the plan as it was, and as the list
  of goals and their status. The dates they give each goal are no longer
  targets. There is no weekly re-plan; the standing Thursday or Friday re-plan
  and the Sunday-night handoff they describe are retired. The TimeAssembler task
  for that re-plan had already been closed.
- **The outer limits stay.** The first kill date, 2026-10-18, still binds the
  registration commit. The second, 2026-11-01, still binds the launch of the
  remaining eight registered runs. The wrap-up start, 2026-12-21, and the
  hibernation deadline, 2027-01-04, are unchanged. Passing a kill date still
  takes a fresh ruling naming what comes off the back end (ruled 2026-09-21).
- **It continues an earlier ruling.** On 2026-09-21 John ruled that work is
  measured in task time, not calendar time: "We are not working on a delayed
  calendar. We are working on a finish every task as quickly as possible mode"
  (`docs/outside-review-protocol.md`, Amendments). The weekend roadmap was
  later laid over that as a schedule. This ruling takes the schedule off again.

## What this does not change

No gate, check, review tier or spending rule changes. A step that waits on John
(a ruling, a go, the outside-review sessions) still waits on him. It is simply
not given a date.
